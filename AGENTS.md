# pr-bot engineering principles

pr-bot is the independent PR reviewer for Jiaze-Li's repositories. Other model entry points (CLAUDE.md etc.) only point here.

**Target: simple, direct, usable.** One default entry, one review workflow, one executor, one authoritative state comment, one rule set.

- Every non-draft PR in a managed repository follows the same path. No modes, labels, providers or commands select a strategy.
- Independent static review, real full coverage, P0/P1/P2 block, P3 never blocks, bounded spend, recovery on the same PR.
- The bot-authored state comment (`docs/review-contract.md`) is the only authority; the commit status is its projection. No database, ledger, queue or controller.
- pr-bot owns the result contract. `docs/review-contract.md` and `tests/fixtures/review-contract.json` (generated by `npm run review:fixtures` from the real code) are the single source consumers pin by commit SHA.
- Do not add: a second provider or fallback chain, a plugin or registry layer, mode switches, a funds ledger, extra gates, mandatory plan/design documents.
- Keep the security core: webhook signature and trigger permission, full pagination, trusted-author check, exact HEAD binding, safe snapshot, read-only tools, no GitHub credentials for the model, schema-validated output.
- Real verification before "done": `npm test` and `npm run test:compat`.
