# brief — CRB-DESIGN-01-S2：合同审核功能的前半段

**状态：已由用户于 2026-11-11 确认，冻结。** agent 不得修改本文件；认为它有问题时停下来报告。

## 1. 目标

给 bot 加上"审合同"功能的前半段，让它能：

- 认出 `@gemini design`、`@claude design`、`reset design` 三条命令；
- 读懂任务清单，检查要审的文件是否合规；
- 在 PR 上写出合同审核的状态评论；
- 提供一个判定脚本，告诉 agent 下一步该等、该改、该重新送审，还是可以继续。

这一阶段**不调用任何模型，不花钱**。真正让模型去审合同是下一阶段。

## 2. 不做什么

- 不调用 Gemini 或 Claude。
- 不改现有"审代码"功能的任何行为。
- 不部署到线上，不合并。
- 不加回之前删掉的机制：请求签名、审查规范授权、防泄露检查、人类账号名单。

## 3. 已经定下的决定

- 按设计文档 v0.6 实现。它已于 2026-11-11 通过独立审查。
- 只考虑你一个人、在你自己的仓库里使用（CRB-DEC-04）。
- brief 变了就停，是流程规则，不是强制机制（CRB-DEC-03）。
- 所有合同审核排成一队，一次只跑一个。GitHub 最多保留 100 个排队中的请求。
- 以下四个数值已随本 brief 一并确认：
  - 合同审核最多 3 轮；
  - 单个文件最大 64 KiB，全部文件合计最大 256 KiB；
  - 一次运行最长 20 分钟；
  - "进行中"超过 30 分钟视为已中断。

## 4. 怎样算做完

1. 现有的 592 个测试全部通过，"审代码"相关的文件一个字节都没变。
2. 三条新命令能被认出；所有旧命令的行为和以前完全一样。
3. 各种不合规的输入（没有清单、多份清单、格式错、文件缺失、文件过大、PR 在途中变了）都得到正确的"没审成"状态，并且没有任何模型调用。
4. brief 被改动后，bot 停下并说明原因；`reset design` 之后可以重新开始，已记录的花费不清零。
5. 判定脚本对每一种状态都给出正确的动作，绝不会对没审过的内容说"可以继续"。
6. 合同审核的评论不会被"审代码"功能认错，即使评论里混入了对方的标记。

## 5. 授权到哪一步

**做到代码审查通过。**

允许：改代码、提交、推送到任务分支、开草稿 PR、转为 Ready、跟进 bot 的代码审查直到 READY。

不允许：合并、部署 Cloudflare Worker、新增或修改密钥和 App 权限、任何付费的合同审核调用、改动分支保护。
